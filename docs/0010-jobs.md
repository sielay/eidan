# 0010 — Jobs (delegation work-queue)

Status: **Shipped** — `@eidandev/jobs` over `eidan.jobs`.

## Goal

A durable work-queue for **delegated** work: anything the agent (or a plugin, or a schedule) wants
run out-of-band — a background task, a coding loop iteration, a scheduled routine — is an `eidan.jobs`
row, claimed and run by a worker. Routing is by **capability `kind`**, not by node or repo, so any
node that handles a kind can pick the work up.

## How it works

- **One table, `eidan.jobs`** — `kind`, `goal`, `payload` (jsonb), `user_id`, `status`
  (`queued → claimed → running → done | failed | cancelled`), `result` (jsonb), `claimed_by`,
  timestamps.
- **Enqueue** = insert a row: `INSERT INTO eidan.jobs (kind, goal, payload, user_id, status) VALUES
  (…, 'queued')`. (No service wrapper yet — plugins insert directly; the routines loop does exactly
  this.)
- **Worker loop** (`startJobWorker`) polls (default 2s) and `claimOne` atomically grabs one queued
  job of a handled kind via `… FOR UPDATE SKIP LOCKED`, so multiple nodes never double-claim. It
  marks `running`, runs the handler, and stores `result` (or the error + `failed`).
- **Handlers by kind** — the `JobHandlers` service (`services.JobHandlers?.register(kind, handler)`)
  lets bundles add capabilities: Sage registers `'code'`, etc. An unhandled kind falls back to the
  default turn handler.
- **Default `chat` handler** (`makeTurnHandler`) runs the job's `goal` as a single agent turn **under
  the job's owner** (`runAs({ id: job.user_id, type: 'user' })`), so the conversation + any memory
  writes persist as that user, and returns the final assistant text in `result`.

## Output / delivery

The handler's return is stored on `eidan.jobs.result`; **delivery is the handler's job** — e.g. a
routine handler emits via `@eidandev/notify` / `TelegramChats`. The default turn handler only stores
the text (the UI reads it back).

## Config

| Env | Default | Meaning |
|---|---|---|
| `EIDAN_JOB_KINDS` | `chat` | comma list of kinds this node's worker claims (e.g. `chat,code`). |
| `EIDAN_JOB_PROVIDER` | `claude` | provider for the default turn handler. |
| `EIDAN_NODE_ID` | `mb-<rand>` | identifies the claiming node (`claimed_by`). |

A node only runs work for kinds in `EIDAN_JOB_KINDS`; to run e.g. Sage coding jobs, the node must
list `code` **and** load the bundle that registers the `code` handler.
